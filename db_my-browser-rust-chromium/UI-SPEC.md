# UI spec — what "EXACT SAME UI as qute" actually means

Extracted from `db_my-browser-qute` on 2026-08-29 by reading the source, not by
eyeballing screenshots. Every value below is quoted from a file; where a value is
**not set anywhere**, that is stated instead of guessed.

## Row order, top to bottom

`mainwindow.py:419-451` builds a `QVBoxLayout` with zero margins and zero spacing,
then inserts at index 0 twice — pinbar first, then mybar — so the final order is:

| Row | Widget | Class | Source |
|---|---|---|---|
| 1 | bookmarks + plugins bar | `MyBar(QToolBar)` | `mybar.py:133` |
| 2 | pinned shortcuts | `PinBar(QTabBar)` | `mybar.py:209` |
| 3 | normal tabs | qutebrowser `TabWidget`/`TabBar` | `tabwidget.py` |
| — | web content | | |
| bottom | statusbar | `StatusBar` | `statusbar/bar.py` |

Pinned tabs are hidden from row 3 — `tabwidget.py:668-669,727-728` force their
size to `QSize(0,0)` and skip them in `paintEvent`.

## Row 2 (PinBar) has NO styling — read this before replicating

`PinBar` sets no stylesheet, no `QStyle`, no font, no color, no padding, no
height. It is a **stock `QTabBar` drawn by the host's native Qt theme**. Contrast
row 3's `TabBar`, which does set `TabBarStyle()` and a `STYLESHEET`
(`tabwidget.py:385-394`).

There are also no `colors.tabs.pinned.*` keys in `qute-settings.json`, and
qutebrowser's own pinned-tab defaults never render, because row 3 paints pinned
tabs at zero size.

**Consequence for the replica:** there is no "exact" pinned-row appearance to
copy — it is whatever Breeze draws today. Matching row 3's palette above is the
sane target, and is arguably an improvement rather than a regression. Do not
invent hex values and call them "qute's".

## Row 2 labels

`mybar.py:240-272` — `names.get(_pinned_tab_url(tab)) or title`. `mybar.json`'s
`pinned[].name` wins; the live page `<title>` is only a fallback for tabs pinned
by hand.

## `mybar.json` schema  (`dist/mybar.json`, generated by `gen-dashboard.sh`)

- `bookmarks[]`: `{name, icon?, url}` → button, or `{name, icon?, links:{label:url}}` → dropdown
- `pinned[]`: `{name, url}` → seeds a pinned tab; `name` overrides the label
- `plugins[]`: `{name, icon?, command}` → toolbutton running a qute command

Current `pinned` set: Bookmarks, Home Files (`http://localhost:8000`), Web
Search, watchdog.

## Statusbar contents

Default `statusbar.widgets`, not overridden: `keypress`, `search_match`, `url`,
`scroll`, `history`, `tabs`, `progress`.

URL is mouse-selectable with an I-beam cursor, and **double-click yanks the whole
URL** to the clipboard (`statusbar/url.py:70-93`) — not one word, which is what a
plain QLabel would do.

## Keybindings  (`src/2_configs/qute-keybindings.json`)

Shape: `mode → key → {cmd, desc, group}`. `insert` and `command` modes are empty.

Tabs: `<Tab>` next · `<Shift-Tab>` prev · `t` open-tab prompt · `T` new blank tab ·
`w` close · `W` tab-only · `q` close window · `u` undo · `<` / `>` move ·
`<Ctrl-p>` pin · `<Ctrl-m>` mute

Navigate: `H` back · `L` forward · `<Alt-Left>` / `<Alt-Right>` back/forward ·
`<Alt-Up>` bookmarks · `r` reload · `R` force reload · `<F5>` reload ·
`<Escape>` stop · `<F11>` fullscreen

URL / clipboard: `o` open · `O` open-tab · `e` edit url · `E` edit url in tab ·
`Y` yank url · `p` / `P` paste-open

Pages: `gD` downloads · `gI` history · `gS` settings · `<F12>` devtools

Autofill: `<Ctrl-Shift-p|u|l|o>` → `da_autofill-rbw-rofi pick|user|pass|totp`

Leader: `,d` bookmarks · `,s` shortcuts · `,e` config-edit · `,v` vault ·
`,a` auth · `,g` git

Injected by `home-module.nix:253-260`, NOT in the JSON: `<Ctrl-Shift-n>`
default_window · `<Ctrl-Shift-t>` open_saved_tabs · `,pp` plugins page · and
`pluginKeybinds` (`,pa` adblock · `,pj` javascript · `,pd` dark-mode ·
`,pf` anti-fingerprint · `,pm` no-autoplay).

> Checked 2026-08-29: `pluginKeybinds` is built from `cfgPlugins`, which filters to
> `surface == "config"` plugins having an `option`. The `autofill-daemon` plugin is
> `surface: "daemon"` with no `option`, so its `keybinding` field never reaches the
> merge. `<Ctrl-Shift-p>` therefore resolves to the rbw-rofi picker as intended —
> there is **no** collision, despite the two files appearing to both claim the key.
